## 🧠 AI/ML 前沿论文

**[LLaDA-Image: Building Strong Image Generators with Fully Open Training Recipes](https://huggingface.co/papers/2609.03796)**
🔬 突破：把扩散语言模型（LLaDA）直接复用到图像生成——6B DiT 从头训练，先做纯图像预训练（220M 样本中 98 个为真实图像）再接入视觉语言模块，打破了过去"生图必须从配对图文数据起步"的假设。训练中用无参数 RMSNorm + Muon 优化器替代 AdamW，Muon 在 6B 规模下把优化器显存占用降约 50%。
⚙️ 工程影响：训练管线被拆成 image-only 预训练 + 后期对齐两阶段，意味着没有高质量图文对的小团队可以先用海量公开图像预训练，再在少量配对数据上微调；Muon 优化器若在 6B DiT 上验证有效，值得在自家视频生成预训练中替换 AdamW 做一次对比实验。

**[Rethinking On-Policy Distillation of LLMs II: One Training Example](https://huggingface.co/papers/2609.04172)**
🔬 突破：把 on-policy distillation（学生生成轨迹 + 老师逐 token 监督）压缩到数据极限——只用一个 query 训练，学生性能竟能持续提升数百步并恢复 full-data OPD 的大部分增益。解释是：单 query 的 on-policy  rollout 天然覆盖训练中访问到的状态分布，且学生向老师对齐的速率快于分布漂移。
⚙️ 工程影响：如果单 query 即可逼近全量蒸馏效果，那主流蒸馏管线（动辄百万级指令数据）的采集成本可显著压缩。验证路径：用内部 10 万条指令集蒸馏出一个 7B，再只用其中 1 条蒸馏一次，对比两者在 5 个下游任务上的差距——若差距 <15%，说明数据多样性对 OPD 的边际收益被高估。

**[Principia: Relational Physics Tests for Video Models](https://huggingface.co/papers/2609.04200)**
🔬 突破：用"同一场景两物体运动必须满足物理关系"替代绝对运动测量，绕开了帧率、物体尺度、相机标定等干扰因素，构建了覆盖重力、碰撞等 8 类物理现象的评测基准。此前视频模型的物理推理评测（如 CLEVRER）依赖标注和标定，结果不可比。
⚙️ 工程影响：视频生成模型（Sora 类）的物理一致性从此有了可自动打分的指标——同一画面内两球的加速度比应恒定，无需外部标定即可定量评估。做视频生成评测基础设施的团队可直接复现该关系式检测器，用于自家模型的回归测试门禁。

**[LatentPress: Context Compression Beyond Text and Vision](https://huggingface.co/papers/2609.01507)**
🔬 突破：把长上下文压缩成"连续记忆 token"，冻结的 decoder 通过 input-embedding 接口直接读取，推理时无需重建文本——压缩 4-16 倍，仅训练一个 4.2M-26.2M 参数的 adapter（约为 decoder 的 0.1%）。在 LongMemEval 上达到 0.504 准确率（7.7 倍压缩）。
⚙️ 工程影响：对比传统 context distillation 输出文本摘要或图片压缩，LatentPress 的压缩产物是连续向量，意味着 token 预算中不再需要为"压缩后的文本"预留可读格式开销。对长对话缓存/多轮 agent 记忆系统有直接价值；但 adapter 与具体 decoder 绑定，换模型需重新训练。

**[Environment Evolution for Terminal Agents](https://huggingface.co/papers/2609.04128)**
🔬 突破：不从头合成新环境，而是用"渐进难化"策略——在已有环境上迭代施压，使环境始终保持在模型当前可学习的前沿。这解决了 co-evolution 方法（依赖 on-policy rollout）在模型变强后学习信号衰减的问题。
⚙️ 工程影响：终端 agent 后训练（terminal agent post-training）的环境成本被显著压缩——不再需要为每个新模型重新合成环境，而是维护一个动态难化的环境池。做 agent 训练数据管线的团队值得读：环境复用率 ↑ 意味着合成预算可重新分配。

The plugin system supports custom notification channels, but device fingerprinting relies on vendor OUI libraries, causing white-label IoT devices to show up largely as "Unknown."
🎯 This week: deploy the container on a test network segment and connect 3 physical subnets to verify if change alert latency is <10 minutes, determining if it can replace the existing Nagios asset discovery module.

**[deep-swe](https://github.com/datacurve-ai/deep-swe)** `Python` ⭐1,598 +24

Compared to SWE-bench's "single-file patch" short tasks, it requires agents to modify multiple files and run tests for self-verification, distinguishing models with similar short-task scores but different long-task persistence. Limitations: only 100+ tasks, high manual annotation cost, and currently no support for custom task injection, making it unable to evaluate internal proprietary codebase scenarios.
🎯 This week: run it against the two strongest internal coding agents (e.g., Claude + proprietary), comparing whether their completion rate difference on long tasks exceeds 20%, to decide inference cache allocation strategy.

**[OpenReplay](https://github.com/openreplay/openreplay)** `TypeScript` ⭐12,663 +30

## 🧠 AI/ML Frontier Papers

**[LLaDA-Image: Building Strong Image Generators with Fully Open Training Recipes](https://huggingface.co/papers/2609.03796)**
🔬 Breakthrough: Directly reuses the diffusion language model (LLaDA) for image generation—a 6B DiT trained from scratch, starting with pure image pretraining (98 real images out of 220M samples) before integrating vision-language modules, breaking the past assumption that "image generation must start from paired image-text data." Training uses parameter-free RMSNorm + Muon optimizer instead of AdamW; Muon reduces optimizer memory usage by ~50% at the 6B scale.
⚙️ Engineering Impact: The training pipeline is split into image-only pretraining + later alignment phases, meaning small teams without high-quality image-text pairs can pretrain on massive public images first, then fine-tune on small paired datasets. If Muon proves effective on 6B DiT, it's worth running a comparative experiment replacing AdamW in your own video generation pretraining.

**[Rethinking On-Policy Distillation of LLMs II: One Training Example](https://huggingface.co/papers/2609.04172)**
🔬 Breakthrough: Compresses on-policy distillation (student-generated trajectories + teacher token-level supervision) to the data limit—training with just one query, the student's performance continuously improves over hundreds of steps and recovers most of the gains from full-data OPD. Explanation: a single query's on-policy rollout naturally covers the state distribution visited during training, and student-teacher alignment outpaces distribution drift.
⚙️ Engineering Impact: If a single query can approximate full-data distillation results, the collection cost for mainstream distillation pipelines (often millions of instruction data points) can be significantly reduced. Validation path: distill a 7B model using 100k internal instruction sets, then distill again using only 1 instruction, comparing performance across 5 downstream tasks—if the gap is <15%, the marginal benefit of data diversity for OPD is overestimated.

**[Principia: Relational Physics Tests for Video Models](https://huggingface.co/papers/2609.04200)**
🔬 Breakthrough: Replaces absolute motion measurement with "two objects in the same scene must satisfy physical relations," bypassing confounders like frame rate, object scale, and camera calibration, building a benchmark covering 8 physical phenomena including gravity and collision. Previous physics reasoning evaluations for video models (e.g., CLEVRER) relied on annotations and calibration, making results incomparable.
⚙️ Engineering Impact: Video generation models (Sora-like) now have an automatically scorable metric for physical consistency—the acceleration ratio between two balls in the same frame should be constant, enabling quantitative evaluation without external calibration. Teams building video generation evaluation infrastructure can directly reproduce this relational detector for regression testing gates on their own models.

**[LatentPress: Context Compression Beyond Text and Vision](https://huggingface.co/papers/2609.01507)**
🔬 Breakthrough: Compresses long contexts into "continuous memory tokens" that a frozen decoder reads directly via the input-embedding interface, without needing to reconstruct text during inference—achieving 4-16x compression by training only a 4.2M-26.2M parameter adapter (~0.1% of the decoder). Reaches 0.504 accuracy on LongMemEval (7.7x compression).
⚙️ Engineering Impact: Compared to traditional context distillation outputting text summaries or image compression, LatentPress's compressed output is continuous vectors, meaning no readable format overhead needs to be reserved for "compressed text" in the token budget. Direct value for long conversation caching/multi-turn agent memory systems; however, the adapter is tied to the specific decoder, requiring retraining for model changes.

**[Environment Evolution for Terminal Agents](https://huggingface.co/papers/2609.04128)**
🔬 Breakthrough: Instead of synthesizing new environments from scratch, uses a "progressive difficulty increase" strategy—iteratively applying pressure on existing environments to keep them at the frontier of the model's current learnability. This solves the issue of co-evolution methods (relying on on-policy rollouts) where learning signals decay as models become stronger.
⚙️ Engineering Impact: The environment cost for terminal agent post-training is significantly reduced—no longer needing to re-synthesize environments for each new model, but maintaining a dynamically hardened environment pool. Teams building agent training data pipelines should read this: higher environment reuse rates mean synthetic budgets can be reallocated.

**[OpenAI/Claude/Grok同時ダウン：推論インフラの隠れた共通原因]**：3つの独立したサービスプロバイダーがほぼ同時刻に利用不能になり、HNとRedditの議論は共有上流（Azureリージョナル可用性ゾーン）と同期リリースプロセス（同日の新モデル設定プッシュ）を指摘。エンジニアリングチームへの直接的な影響：LLM APIのフォールバックを単一クラウドベンダーに依存するだけでは不十分——2つのクラウドベンダー間で推論トラフィックのactive-activeルーティングを行うか、少なくとも重要なエージェントタスク用にローカル小モデルのフォールバックパス（例：K2-Horizon-32B-GGUFを単一4090で実行）を確保する必要があります。
