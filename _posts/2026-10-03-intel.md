## ⚡ 趋势信号

**决策模型从"云厂商 API"下沉到"本地推理框架原生支持"**：llama.cpp 今天加入 decision models 支持，配合 Clef-flash 的 39ms 和 Apache 2.0，判断类任务（路由、审核、打分）第一次可以完全离线跑在 CPU 上。延续 9-26 以来"校准决策模型成为独立品类"的线，但性质变了——之前是三家云厂商抢着卖 API，现在是推理框架把它变成默认能力，自托管成本趋近于零。
> 参考 10-02：Cloudflare Clef + AWS Strands Decider 同日发布，一周内三家云厂商入场。

**平台层开始为 agent 单独设计权限模型，而不是复用人类权限**：Apple 的 FDA 收紧是第一个明确以"agent 风险"为由改 OS 权限的案例，Nvidia OpenShell（9-29）走的是运行时沙箱路线，两条路指向同一个结论——prompt 层的权限约束不被信任了。对工程决策的影响：本地 agent 的权限设计现在要同时考虑 OS 授权流程和运行时沙箱，纯 prompt 约束的方案在 macOS 上会先失效。

## ⚡ Trend Signals

**Decision models sinking from "cloud vendor APIs" to "native support in local inference frameworks"**: llama.cpp added decision models support today, combined with Clef-flash's 39ms and Apache 2.0, judgment-type tasks (routing, moderation, scoring) can for the first time run entirely offline on CPU. This continues the thread since 9-26 of "calibrated decision models becoming an independent category," but the nature has changed—previously three cloud vendors were racing to sell APIs, now the inference framework makes it a default capability, with self-hosting costs approaching zero.
> Reference 10-02: Cloudflare Clef + AWS Strands Decider released the same day, three cloud vendors entered within a week.

**Platform layer begins designing permission models specifically for agents, rather than reusing human permissions**: Apple's FDA tightening is the first case of explicitly changing OS permissions on grounds of "agent risk," while Nvidia OpenShell (9-29) takes the runtime sandbox route. Both paths point to the same conclusion—prompt-layer permission constraints are no longer trusted. Impact on engineering decisions: local agent permission design now needs to consider both OS authorization flows and runtime sandboxes; pure prompt-constraint solutions will fail first on macOS.
