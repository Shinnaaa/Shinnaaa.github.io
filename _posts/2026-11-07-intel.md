## 📌 今日要闻

**1. Ripple-65B Preview：Apache 2.0 全开放权重，TerminalBench 2.1 上美国开源模型第一，研发总成本 3200 万美元**  
Ricursive Intelligence 把"美国开源模型"这个此前基本空着的格子填了：65B 全权重、Apache 2.0（不是 Llama 那种带条款的"开放"），在 agentic coding 基准上拿到美国开源第一。但报道自己承认其他 benchmark 表现一般——这是典型的"单点打穿"策略，选它是因为 coding agent 是当前唯一能直接变现的场景。对在评估 Claude Code / Codex 替代方案的团队，这是第一个可以合法私有化部署、且不用谈商业授权的 65B coding 模型；先跑一遍你自家仓库的 SWE 任务，别信 TerminalBench 分数。 · [The Decoder](https://the-decoder.com/ripple-65b-preview-delivers-strong-agentic-coding-results-as-a-fully-apache-2-0-open-us-model/)

**2. Chainalysis 承认全部客户的凭证和 token 被窃，攻击含 AI agent 与 on-path 数据截取**  
区块链取证公司自己成了被取证对象，且失窃范围是"所有客户"——不是部分。攻击手法里明确写了 AI agents 参与，这是本周第二起把 AI 作为攻击组件而非攻击目标的公开案例（第一起是 11-06 的 GPT-6 Cyber）。用 Chainalysis 做 KYT/合规的交易所和支付团队，今天要做的不是等通知，而是假设自家 API key 已泄露并立即轮换。 · [Ars Technica](https://arstechnica.com/security/2026/11/chainalysis-says-hackers-stole-credentials-and-tokens-for-all-of-its-customers/)

**3. Anthropic IPO 买方估值低至 1.1 万亿美元，同时 Ramp 数据显示 AI 支出正在停滞**  
两个来源指向同一件事：企业 AI 支出曲线在 IPO 前夜走平。Ramp 的刷卡数据是少数能反映真实企业支出的高频指标，它停滞意味着"AI 预算无限增长"的假设开始失效。对做多模型路由和成本优化的团队，这是利好——供应商议价能力下降，12 月 ChatGPT 配额改制（11-02 已报）之后大概率还有一轮降价。 · [Bloomberg](https://www.bloomberg.com/news/articles/2026-11-06/anthropic-ipo-valuation-expectations-pressured-after-ai-rout) / [TechCrunch](https://techcrunch.com/2026/11/06/ramp-data-shows-ai-spending-stalling-just-as-anthropic-nears-its-ipo/)

**4. 数百个 Artex AI 渗透测试工具实例裸奔在公网**  
AI 红队工具本身成了攻击面：这些实例无鉴权暴露，任何人可调用。和 11-06 的 GPT-6 Cyber 放在一起看，本周的主题是"攻击能力正在被 AI 商品化，而部署它的人不懂运维"。自查一遍你团队内部跑的 LLM 安全工具是否有公网入口。 · [TechCrunch](https://techcrunch.com/2026/11/06/hundreds-of-artex-ai-hacking-tools-found-publicly-exposed-to-the-web/)

## ⚡ 趋势信号

**Agent 上下文压缩从"摘要文本"转向"潜空间"**：今天两篇独立论文（Coca-Cola 的 latent context compression、SwarmEvolve 的 KV cache 传递）都在做同一件事——不再把工具输出解码成 token 塞回上下文。Coca-Cola 明确指出 token pruning/summarization 的压缩率被离散文本表示卡住上限。对搭 agent 框架的团队，这意味着"上下文管理"这一层的实现方式可能在两个季度内换掉，现在别把摘要策略硬编码进业务逻辑。
> 7 天内的相关线索：11-03/11-04 的 weight-space programming 争议说明"绕过文本表示"这条路正在被多方试探，但验证标准还没建立。

**开源模型的"开放"定义正在分裂成两档**：Ripple-65B 用 Apache 2.0 全权重，腾讯 Hy4 只发博客不发权重（11-05），Qwen 系被大量微调但基座条款各异。选型时"开源"这个词已经没有信息量，必须落到许可证 + 权重可得性 + 商用条款三项分别核对。
> 延续 11-05 的判断（Hy4 权重未放），今天 Ripple 提供了反例，两档分化更清晰。

## ⚡ Trend Signals

**Agent context compression is shifting from "summarized text" to "latent space"**: Two independent papers today (Coca-Cola's latent context compression, SwarmEvolve's KV cache passing) are both doing the same thing—no longer decoding tool outputs into tokens and stuffing them back into context. Coca-Cola explicitly points out that the compression ratio of token pruning/summarization is capped by discrete text representation. For teams building agent frameworks, this means the implementation of the "context management" layer may be replaced within two quarters; don't hardcode summarization strategies into business logic now.
> Related clues within 7 days: the weight-space programming controversy on 11-03/11-04 shows that the path of "bypassing text representation" is being probed by multiple parties, but validation standards have not yet been established.

**The definition of "open" for open-source models is splitting into two tiers**: Ripple-65B uses Apache 2.0 full weights, Tencent Hy4 only publishes a blog without releasing weights (11-05), and the Qwen family is widely fine-tuned but with varying base model terms. When selecting models, the word "open source" no longer carries information; you must check three items separately: license + weight availability + commercial terms.
> Continuing the judgment from 11-05 (Hy4 weights not released), today Ripple provides a counterexample, making the two-tier split clearer.

## ⚡ トレンドシグナル

**Agent のコンテキスト圧縮が「要約テキスト」から「潜在空間」へ移行**：今日の 2 本の独立した論文（Coca-Cola の latent context compression、SwarmEvolve の KV cache 伝達）はいずれも同じことをしている——ツール出力をトークンにデコードしてコンテキストに戻すのをやめた。Coca-Cola は token pruning/summarization の圧縮率が離散テキスト表現によって上限を塞がれていると明確に指摘している。agent フレームワークを構築するチームにとって、これは「コンテキスト管理」という層の実装方式が 2 四半期以内に置き換わる可能性があることを意味するので、今は要約戦略をビジネスロジックにハードコードしないこと。
> 7 日以内の関連手がかり：11-03/11-04 の weight-space programming 論争は「テキスト表現を迂回する」という道が多方面から模索されていることを示すが、検証基準はまだ確立されていない。

**オープンソースモデルの「オープン」の定義が 2 段階に分裂しつつある**：Ripple-65B は Apache 2.0 の全ウェイト、Tencent Hy4 はブログのみでウェイト非公開（11-05）、Qwen 系は大量にファインチューニングされているが基盤の条項は様々。選定時に「オープンソース」という言葉はもはや情報量を持たず、ライセンス + ウェイトの入手可能性 + 商用条項の 3 項目をそれぞれ照合する必要がある。
> 11-05 の判断（Hy4 ウェイト未公開）を引き継ぎ、今日 Ripple が反例を提供したことで、2 段階の分化がより明確になった。
