## 📌 今日要闻

**1. Goldman Sachs 把 Claude Code 从交易员和银行家手里收回，HN 669👍**  
这是首个大型金融机构公开撤回编码 agent 的案例，理由不是模型能力而是合规与审计边界——受监管岗位的代码变更需要可追溯的责任人，agent 生成的 diff 无法满足。对在金融、医疗等受监管行业推 agent 的团队，这条把"agent 能不能写生产代码"变成"agent 写的代码谁签字"，本周该做的是把 agent 输出纳入现有变更审批流而不是另开一条通道。 · [The State of AI](https://www.thestateofai.com/news/goldman-sachs-claude-code-traders-bankers)

**2. 阿里 Co-Design Bench：GPT-6 Astra 在真实用户请求上只完整解决 26.4%，旧基准同模型 99%+**  
基准用的是"实际把 agent 卡住过的真实请求"，不是合成任务。26.4% 与 99% 的落差说明现有 SWE-bench 类评测已经失去区分度，任何按旧基准分数做选型的决策都需要重跑。对正在评估 Ripple-65B、mini-swe-agent 这类方案的团队，这是本周唯一该看的数字——先确认你的评测集里有多少是"真实失败过的请求"。 · [The Decoder](https://the-decoder.com/ai-coding-agents-still-need-human-cleanup-on-nearly-three-out-of-four-tasks-in-a-real-world-test/)

**3. Karpathy 用 Claude Opus 5.5 一个周末把 4300 万条 HN 评论筛成 6,454 个视频，称效果超过 YouTube 推荐**  
单次长上下文批处理 + 结构化筛选，一个人两天完成过去需要推荐系统团队数月的工作。可复现的部分是"用 LLM 做离线内容策展"这条流水线：43M→6.4K 的压缩比意味着每千条评论约 0.15 个产出，成本可算。对做内容检索或知识库的团队，值得抄的是它的筛选 prompt 结构而不是结果。 · [The Decoder](https://the-decoder.com/andrej-karpathy-built-a-curated-video-platform-in-a-weekend-using-claude-and-20-years-of-hacker-news/)

**4. llama-modchip：284B 的 DeepSeek 在 64GB 内存、无 GPU 上跑起来，HN 388👍**  
把 284B 模型塞进 64GB 消费级内存，靠的是权重分块 + 按需从磁盘换入，代价是吞吐。这条的实际价值不是"能跑"，而是给出了一个可复现的 offload 实现，让本地部署的显存门槛从"多卡"降到"大内存单机"。对在评估私有化部署的团队，先测它的 token/s 再决定是否值得替代 API 调用。 · [GitHub](https://github.com/synchopate/llama-modchip)

**5. Nvidia 董事会调查黄仁勋与疑似中国间谍 Alice Huang 的关系，黄承认婚外情**  
CEO 层面的安全事件，Megaspeed 高管被指受中国国安部招募对 Nvidia 进行情报活动。对采购 Nvidia 算力或与其有供应链关系的团队，短期影响是出口管制与合规审查可能收紧，长期看是 AI 芯片供应链的政治风险溢价。 · [TechCrunch](https://techcrunch.com/2026/11/08/nvidia-says-its-investigating-ceo-jensen-huangs-relationship-with-possible-chinese-spy/) / [The Verge](https://www.theverge.com/ai-artificial-intelligence/1029562/nvidia-investigating-jensen-huang-relationship-chinese-spy)

## ⚡ 趋势信号

> 延续 11-07 Ripple-65B 的 Apache 2.0 全权重发布——可私有化的 coding 模型供给在增加，瓶颈从"有没有权重"变成"跑不跑得动"。

## 📌 Today's Top Stories

**1. Goldman Sachs pulls Claude Code back from traders and bankers, HN 669👍**  
This is the first case of a major financial institution publicly withdrawing a coding agent, and the reason isn't model capability but compliance and audit boundaries—code changes in regulated roles require a traceable responsible party, and diffs generated by agents cannot satisfy this. For teams pushing agents in regulated industries like finance and healthcare, this shifts the question from "can an agent write production code" to "who signs off on code written by an agent." What to do this week is fold agent output into your existing change approval flow rather than opening a separate channel. · [The State of AI](https://www.thestateofai.com/news/goldman-sachs-claude-code-traders-bankers)

**2. Alibaba Co-Design Bench: GPT-6 Astra fully solves only 26.4% of real user requests, versus 99%+ on old benchmarks for the same model**  
The benchmark uses "real requests that actually stumped agents," not synthetic tasks. The gap between 26.4% and 99% shows that existing SWE-bench-style evaluations have lost their discriminative power, and any selection decision based on old benchmark scores needs to be re-run. For teams evaluating options like Ripple-65B and mini-swe-agent, this is the only number worth looking at this week—first confirm how many requests in your eval set are "requests that actually failed before." · [The Decoder](https://the-decoder.com/ai-coding-agents-still-need-human-cleanup-on-nearly-three-out-of-four-tasks-in-a-real-world-test/)

**3. Karpathy uses Claude Opus 5.5 over a weekend to filter 43 million HN comments down to 6,454 videos, says results beat YouTube recommendations**  
A single long-context batch process plus structured filtering let one person accomplish in two days what used to take a recommendation systems team months. The reproducible part is the "using LLMs for offline content curation" pipeline: the 43M→6.4K compression ratio means roughly 0.15 outputs per thousand comments, and the cost is calculable. For teams working on content retrieval or knowledge bases, what's worth copying is the structure of its filtering prompt, not the results. · [The Decoder](https://the-decoder.com/andrej-karpathy-built-a-curated-video-platform-in-a-weekend-using-claude-and-20-years-of-hacker-news/)

**4. llama-modchip: 284B DeepSeek runs on 64GB of RAM with no GPU, HN 388👍**  
Squeezing a 284B model into 64GB of consumer-grade memory relies on weight chunking plus on-demand paging from disk, at the cost of throughput. The real value here isn't "it runs" but that it provides a reproducible offload implementation, lowering the VRAM barrier for local deployment from "multiple GPUs" to "a single machine with lots of RAM." For teams evaluating private deployment, test its tokens/s first before deciding whether it's worth replacing API calls. · [GitHub](https://github.com/synchopate/llama-modchip)

**5. Nvidia board investigates Jensen Huang's relationship with suspected Chinese spy Alice Huang; Huang admits to extramarital affair**  
A security incident at the CEO level, with a Megaspeed executive alleged to have been recruited by China's Ministry of State Security to conduct intelligence activities against Nvidia. For teams procuring Nvidia compute or with supply-chain ties to the company, the short-term impact is that export controls and compliance reviews may tighten; the long-term view is a political risk premium on the AI chip supply chain. · [TechCrunch](https://techcrunch.com/2026/11/08/nvidia-says-its-investigating-ceo-jensen-huangs-relationship-with-possible-chinese-spy/) / [The Verge](https://www.theverge.com/ai-artificial-intelligence/1029562/nvidia-investigating-jensen-huang-relationship-chinese-spy)

## ⚡ Trend Signals

**The evaluation standard for coding agents is shifting from "can it do it" to "who's responsible once it's done"**: Goldman pulling back Claude Code and Co-Design Bench's 26.4% are two sides of the same thing—capability is already sufficient; the bottleneck is accountability and real-task success rates. When selecting tools, putting "audit trail" and "pass rate on real failure sets" into your evaluation table is more useful than looking at SWE-bench scores.
> Continuing from 11-05 OpenAI's acquisition of Pierre (a permission model for agents pushing directly to main) and 11-08 apiiro's credential leak scanning—all three point to the governance gap once agents enter production. Not a new signal, but today brings the first withdrawal case in the financial industry.

**The memory barrier for local inference is dropping; the VRAM barrier hasn't changed**: llama-modchip's 284B/64GB and ISTA-DASLab's DeepSeek-V4.1-Flash Coder GGUF appearing at the same time shows the community is pushing toward "big-memory single machine + quantization." The cost model for private deployment should be recalculated based on "memory bandwidth" rather than "VRAM capacity."
> Continuing from 11-07 Ripple-65B's Apache 2.0 full-weight release—the supply of privatizable coding models is increasing, and the bottleneck is shifting from "are there weights" to "can you actually run them."

## ⚡ トレンドシグナル

**コーディング agent の評価基準は「できるかどうか」から「やった後誰が責任を負うか」へ移行中**：Goldman による Claude Code 撤回と Co-Design Bench の 26.4% は同じ事象の裏表だ——能力はすでに十分で、ボトルネックは責任の所在と実タスクの成功率にある。選定時には「監査チェーン」と「実失敗セットの通過率」を評価表に入れる方が、SWE-bench のスコアを見るより有用だ。
> 11-05 の OpenAI による Pierre 買収（agent が直接メインブランチへ push する権限モデル）と 11-08 の apiiro による認証情報漏洩スキャンを受けた話——三つとも agent が本番に入った後のガバナンスの空白を指しており、新しいシグナルではないが、今日金融業界で初の撤回事例が出た。

**ローカル推論のメモリ要件は下がっているが、VRAM 要件は変わっていない**：llama-modchip の 284B/64GB と ISTA-DASLab の DeepSeek-V4.1-Flash Coder GGUF が同時に現れたことは、コミュニティが「大メモリ単機＋量子化」の方向へ押し進めていることを示す。プライベートデプロイのコストモデルは「VRAM 容量」ではなく「メモリ帯域」で再計算すべきだ。
> 11-07 の Ripple-65B の Apache 2.0 全重み公開を受けた話——プライベート化可能な coding モデルの供給は増えており、ボトルネックは「重みがあるか」から「動かせるか」へ変わった。
